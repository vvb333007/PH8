# PH8 vs Zend PHP: различия языков и реализации


## 1. Возможности, которых пока нет PH8


- **Деструктуризация с коротким синтаксисом `list`:** `[$a, $b, $c] = $x;` — не поддерживается; запланировано.
- **параметр foreach, идущий после `as` не может быть `list`:**  — не поддерживается;
- **Оператор `??=`:** отсутствует, следует переписать конструкцию под оператор `??`
- **Оператор `**`:** отсутствует, следует использовать `pow($x,$y)`
- **Constructor property promotion:** не поддерживается. Атрибуты класса необходимо объявлять явно.
- **__set():** и некоторые другие magic methods не поддерживаются. Функционал __set() достижим другим способом в PH8 (через __get())


## 2. Возможности PH8, отличающиеся от PHP

**Самая большая** (но не единственная) несовместимость между PH8 и ZendPHP8 состоит в том, что массивы всегда
передаются (и возвращаются) по ссылке - т.е. семантика более Си-шная, где при передаче массива происходт передача указателя.
Если же функции требуется именно копия массива для работы - эта функция должна создать себе такую копию : `$local = array_copy($arg);`

```php
$a = [1,2,3,4];

function hello($az) {

  $az[0] = 10;
  var_dump($az);
}

hello($z);
var_dump($a); // первый элемент будет равен 10
```

Соответственно, операции присваивания массива присваювают ссылку, а не сам массив:


```php
$arr = array(1,2,3);
$b = $arr;
$b[0] = 10;
var_dump($arr); // первый элемент массива равен 10
```

Это осознанный элемент дизайна PH8: связанна такая особенность с ограничениями по памяти в embedded-окружениях: если нерадивый программист везде передает массивы копией, то никаких ресурсов не хватит держать все это в памяти, создавать, тут же удалять.

Для программистов на Си\Си++ такое поведение привычно.

**Отсутствуют union типы** : конструкции вида `int|string|array` не будут компилироваться. Это опять же осознанный выбор и связан он с тем, как PH8 обрабатывает типы (типа аргументов функций, типы атрибутов класса), об это чуть ниже, в главе 3.
(nullable типы, как частный случай union-типа `null|тип` - присутствуют)

### 2.1. Целочисленная арифметика и UTF-8

PH8 использует 64-битную целочисленную арифметику на всех платформах. В PHP размер целого числа зависит от платформы: 32 бита на 32-битных платформах и 64 бита на 64-битных.
PH8 использует double вместо float на всех платформах. 
PH8 также нативно поддерживает UTF-8 для строк, идентификаторов, констант, переменных, имён функций, классов и других подобных сущностей.

### 2.2. Доступ к статическим свойствам через объект

В PH8 к статическим свойствам можно обращаться и присваивать им значения через объект с помощью оператора `->`. В PHP такой синтаксис для статических свойств недопустим.

```php
class MyClass {
    public static $a = 5 * 5;
}

$n = new MyClass;
$n->a <<= 1;

echo MyClass::$a; // Выведет 50
```
### 2.3. Вызов деструкторов при аварии

При аварии у каждого экземпляра класса будет вызван деструктор и, если определен, специальный magic-метод
`__terminate(bool $is_oom, ?string $reason)` который предназначен для аварийного освобождения аппаратных ресурсов, если таковые были аллокированы классом.
В больших системах закрытием всего занимается ОС, в то время как в эмбеддед это зачастую задача программиста.


### 2.4. Перегрузка конструкторов и деструкторов

В PH8 конструкторы и деструкторы могут перегружаться так же, как и другие методы класса. 
Если конструктор отсутствует, атрибуты сохраняют значения инициализации, в том числе полученные в 
результате сложных выражений, а не обнуляются.

В Zend PHP такая перегрузка не поддерживается, а возможности использования сложных выражений ограничены.

### 2.5. Сложные выражения в значениях по умолчанию и константах

В PH8 значениями аргументов по умолчанию могут быть сложные выражения. Аналогичный подход применим к `const`, `static` и значениям `enum`.

Пример:

```php
const Hello = 'Hello' . rand_str(15);

function test($callback = function() {
    echo "Hello World!\n";
}) {
    // Проверяем, что перед нами callback
    if (!is_callable($callback)) {
        die("Expecting a callback");
    }

    // Вызываем callback
    $callback();
}

// Вызов без аргументов
test(); // Выведет: Hello World!

// Вызов с одним аргументом
test(function() {
    echo "Welcome guest\n";
}); // Выведет: Welcome guest

test(10); // Выведет: Expecting a callback
```

### 2.6. Перегрузка функций по количеству и типам аргументов

PH8 поддерживает перегрузку функций по количеству и типам аргументов.Zend PHP такой механизм не поддерживает.

```php
function foo(int $a) {
    echo "a is integer\n";
    var_dump($a);
}

function foo(array $a) {
    echo "a is an array\n";
    var_dump($a);
}

foo(52); // a is integer
foo(array(14, __TIME__, __DATE__)); // a is an array
```

### 2.7. Оператор запятой

В PH8 оператор запятой может использоваться в выражениях. 
Есть возможность перечислять несколько `case` в `enum` через запятую, если для них явно заданы значения.
В ZendPHP оператор 'запятая' как таковой отсутствует. Запятая является частью языковых конструкций и может использоваться только в них: `$a = [1,2,3]`, но не в выражениях.

```php
$a = 25, $b = $a << 1, test();

// Выводим значения $a и $b
function test() {
    global $a, $b;
    echo "\$a = $a \$b= $b\n"; // $a = 25 $b = 50
}

enum Hello: int {
    case A = 1, B = 2, C = 3;
    case H = 66;
}
```

### 2.8. Упрощённая семантика `__call()` и `__callStatic()`

В PH8 реализована более простая и непосредственная семантика магических методов `__call()` и `__callStatic()` по сравнению с Zend PHP 8. Вместо передачи имени отсутствующего метода в качестве первого параметра и всех исходных аргументов, упакованных в один массив, магический метод получает исходные аргументы непосредственно, с сохранением их количества, порядка и обычной семантики передачи параметров. Имя перехваченного метода доступно через специальную константу `__CALL__`. Это избавляет от необходимости распаковывать массив аргументов и позволяет магическим методам работать практически как прозрачные обработчики вызовов несуществующих методов, причём их параметры можно объявлять в соответствии с фактическим набором аргументов перехваченного вызова.

## 3. Система типов и автоматическое преобразование

В PH8, в отличии от Zend PHP, объявленный тип - это гарантия, а не ограничение. Виртуальная машина автоматически приводит значение к нужному типу, когда это необходимо для сохранения этой гарантии.

### Гарантии типов в PH8

* **Input Guarantee - гарантия на входе**

  Код внутри функции или метода может поалгаться на объявленные типы своих аргументов, независимо от того, что фактически передал вызывающий код.

* **Output Guarantee - гарантия на выходе**

  Код, вызывающий функцию или метод, может полагаться на объявленный тип результата, независимо от того, что фактически вернула функция.

* **Encapsulated Data-Type Guarantee - гарантия типов данных внутри объекта**

  Методы и другие члены класса могут полагаться на объявленные типы свойств объекта. Типизированное свойство всегда содержит значение своего объявленного типа, независимо от того, каким образом это значение было присвоено.

### Подробнее

Как и в PHP 8, в PH8 можно указывать типы аргументов функций и методов, а также типы возвращаемых значений.

Но принцип работы здесь другой.

В PHP 8 несоответствие типа считается **ошибкой**, а в PH8 объявленный тип служит **указанием для виртуальной машины**: он говорит VM, **к какому типу нужно привести значение**.

Для аргументов и возвращаемых значений действуют одни и те же правила. Поэтому тип гарантирован как при входе в функцию, так и при выходе из неё.

### Скалярные типы

Допустим, функция объявлена так:

```php
function test(int $a, ?string $b) { /* ... */ }
```

Тогда вызов:

```php
test('66', 12);
```

полностью допустим.

Виртуальная машина преобразует строку `'66'` в число `66`, поскольку первый аргумент имеет тип `int`. Число `12` будет преобразовано в строку `'12'`, поскольку второй аргумент имеет тип `?string`.

То же самое происходит с возвращаемыми значениями. Если функция с типом возврата `: int` вернёт `'66'`, вызывающий код получит `66`.

### Отсутствие типа и nullable-типы

Если тип не указан, автоматического преобразования не происходит. В этом случае тип считается `mixed`, и значение передаётся как есть.

Если тип объявлен как nullable, например `?string`, преобразование применяется только к значениям, отличным от `null`. Сам `null` передаётся без изменений.

### Тип `object`

Если передано или возвращено значение-объект, оно передаётся как есть.

Если значение не является объектом, оно автоматически оборачивается в `stdClass($scalar_value)`. Исходное значение при этом не теряется, а код, ожидающий объект, в любом случае получает объект.

То же относится к `null`. Если для аргумента или возвращаемого значения указан тип `object` без `?`, то `null` также будет преобразован в `stdClass(null)`.

Если `null` должен проходить без изменений, нужно использовать тип `?object`.

### Тип `callable`

Значение считается корректным `callable`, если это строка или массив, указывающий на реально существующую функцию или метод, который можно вызвать. Например:

```php
'strlen'
```

или:

```php
[$obj, 'method']
```

Если значение нельзя преобразовать в `callable`, вместо него создаётся специальная функция `__badcallable` из системной библиотеки.

Для остального кода это полноценный `callable`: `is_callable()` вернёт `true`. Но при первой попытке его вызвать будет выброшено исключение `TypeError`, которое можно перехватить через `try/catch`.

Таким образом, ошибка не теряется. Она возникает в момент фактического использования неправильного значения, а не остаётся незамеченной.

PH8 всегда гарантирует соответствие объявленному типу: скаляры преобразуются, не-объекты (включая `null`) оборачиваются в `stdClass`, а некорректный `callable` заменяется заглушкой, которая выбрасывает `TypeError` при вызове.

### Типизированные свойства класса

Свойства класса также могут иметь объявленный тип:

```php
class Test {
  public static int $z = 0;
  public ?string $a = 'hello';
}
```

Объявленный тип свойства **сохраняется постоянно** - присваиванием значения другого типа его изменить нельзя.

При записи в типизированное свойство PH8 автоматически приводит значение к объявленному типу, если это возможно. Поэтому свойство сохраняет свой тип на протяжении всего времени существования объекта.

Например:

```php
$a = new Test();

$a->a = 123;
```

Значение будет автоматически преобразовано в строку `'123'`, поскольку `$a->a` объявлено как `?string`.

Для свойств класса действуют те же правила преобразования, что и для аргументов функций и возвращаемых значений.



## 4. Функция стрелка

Стрелочные функции PH8 требуют явного захвата внешних переменных через `use`; возвращаемое значение преобразуется к объявленному типу.

```php
fn($x) use ($factor): int => $x * $factor
```

В PH8 внешняя переменная `$factor` захватывается явно. В Zend PHP стрелочные функции автоматически захватывают переменные из внешней области видимости.

## 5. Перечисления (`enum`)

Механизм `enum` в PH8 отличается от реализации Zend PHP несколькими особенностями.

### 5.1. Обычные перечисления

В PH8 case обычного `enum` -- автоматически генерируемые константы. В PHP case обычного перечисления не имеют связанных скалярных значений.

### 5.2. Backed enum и преобразование значений

В PH8 case перечисления могут иметь значения разных типов, в том числе результаты сложных выражений и вызовов функций, даже если у самого `enum` объявлен тип-носитель. Объявленный тип используется для автоматического преобразования значения при потреблении его в контексте этого типа.

В Zend PHP каждый case backed enum должен соответствовать объявленному скалярному типу: например, `int` или `string`.

Значения `enum` типа `string` преобразуются в строки при использовании такого типа.

### 5.3. Смешанные типы и автоматическая нумерация

PH8 допускает перечисления со значениями case разных типов без проверки типов при объявлении. Общего эквивалента такого backed enum в Zend PHP нет.

PH8 также поддерживает автоматическую генерацию значений case. 
Автоматическая нумерация может сочетаться с явно заданными значениями: неявные значения продолжают генерироваться независимо.

### 5.4. Пример перечислений

```php
// Enum без автопреобразования (mixed)
enum Loo: mixed {
    case Name1 = 10;
    case Name2 = 10.2;
    case Name3 = 'Hello' . rand_str(4);
}

// При использовании как Suit $x в аргументах функции
// значение автоматически преобразуется в строку
enum Suit: string {
    case Name1 = 10;
    case Name2 = 10.2;
    case Name3 = 'Hello' . rand_str(4);
}

function test(Suit $x) { // Эквивалентно test(string $x)
    var_dump($x);         // Выведет строковое значение
}

function test(Loo $x) {  // Эквивалентно test(mixed $x)
    var_dump($x);        // Выведет значение с реальным типом
}
```

## 6. Замыкания (`Closure`), `never` и `callable`

### 6.1. Представление замыканий

В PH8 closure представлено как `string|array`. Например:

```php
$a = function() use($x,$y) {};
var_dump($a);
```

выведет `string(9, 'closure_1')` или похожая строка.

В Zend PHP замыкание является объектом со свойствами и методами.


### 6.2. Тип возврата `never`

В PH8 модификатор `:never` автоматически вставляет опкод `HALT`, если выполнение доходит до возврата из функции. Никаких исключений выброшено не будет - произойдет останов программы.

В Zend PHP соблюдение `never` проверяется на этапе компиляции, хотя статический анализ не всегда позволяет проверить это во всех случаях.


## 7. Операторы

### 7.1. Операторы `?:` (Elvis) и `??=` не поддерживаются.

Вместо них следует использовать обычный тернарный оператор `? a : b` и обычный null coalesce оператор `??`

### 7.2. Оператор `?->` (Nullsafe) распостраняет свое действие лишь на свой метод, распостранения null не происходит:

ZendPHP8:  `$a?->method()->method()` - nullsafe нужен лишь единожды. Все выражение оборачивается в null, если сработал первый nullsafe оператор.
Эквивалентная конструкция в PH8 будет записана как `$a?->method()?->method()` : nullsafe указан у каждой стрелки

### 7.3. Приоритет операторов

Таблица приоритетов PH8 ориентирована на язык Си, а не на актуальную таблицу PHP. Это сознательное решение: многие расширения PH8, например перегрузка функций, тоже заимствованы из Си, и единая модель приоритетов делает язык предсказуемым для тех, кто знаком с Си. Порядок основных уровней (постфиксные операторы, унарные, `* / %`, `+ -`, сдвиги, сравнения, равенство, `&`, `^`, `|`, `&&`, `||`, `?:`, присваивания, запятая) совпадает с Си. Поверх него добавлены PHP-специфичные операторы: `instanceof`, `.`, `??`, `->`, `::`, словесные `and`, `xor`, `or`.

Из-за этого в нескольких случаях PH8 разбирает выражения иначе, чем PHP 8. Все такие случаи сводятся к одному правилу: если выражение смешивает операторы из списка ниже, расставляйте скобки явно. Код со скобками работает одинаково в PH8 и в PHP, а заодно читается лучше.

### 7.4. Отличия от PHP 8 и как писать код

**`!` и `instanceof`.** В PHP оператор `instanceof` старше `!`, поэтому `!$a instanceof B` означает `!($a instanceof B)`. В PH8 `!` является обычным унарным оператором, как в Си, и старше `instanceof`, поэтому то же выражение разбирается как `(!$a) instanceof B`. Это самое частое расхождение, потому что такая проверка очень распространена в PHP-коде. Правильная запись:

```php
if (!($a instanceof B)) { ... }
```

**Конкатенация `.` и арифметика.** В PHP 8 приоритет оператора `.` ниже, чем у `+`, `-`, `<<` и `>>`. В PH8 `.` стоит на одном уровне с `+` и `-` (как это было в PHP 7), а сдвиги стоят ниже. Поэтому выражение `"a" . 1 + 2` в PHP 8 даёт `"a3"`, а в PH8 разбирается как `("a" . 1) + 2`. Не смешивайте `.` с арифметикой и сдвигами без скобок:

```php
echo "Итого: " . ($a + $b);
echo "Маска: " . ($x << 2);
```

**`??` и логические операторы.** В PHP `??` стоит ниже `||` и правоассоциативен. В PH8 он находится на одном уровне с `||` и левоассоциативен. Цепочки вида `$a ?? $b ?? $c` дают одинаковый результат, но `$a ?? $b || $c` разбирается по-разному. Если `??` используется вместе с `||` или `&&`, указывайте порядок скобками:

```php
$x = $a ?? ($b || $c);
$y = ($a ?? $b) || $c;
```

**`<>`.** В PHP `<>` является синонимом `!=` и стоит на уровне равенства. В PH8 он стоит на уровне `<`, `>`, `<=`, `>=`. В выражении без скобок, где он смешивается с `==` или `!=`, результат может отличаться. Лучше писать `!=`.

**Ссылочное присваивание `=&`.** В PH8 этот оператор имеет приоритет `&` и левоассоциативен, тогда как в PHP это обычное присваивание. Используйте его только в простой форме `$a =& $b;`, не комбинируя с другими операторами в одном выражении.

**Присваивание внутри условия.** Выражения вида `!$x = f()` в PHP означают `!($x = f())`. Чтобы не зависеть от особенностей разбора, пишите так:

```php
if (!($x = f())) { ... }
```
**`??` и `||`.** В PHP оператор `??` имеет приоритет ниже, чем `||`, и правоассоциативен. В PH8 `??` и `||` находятся на одном уровне и оба левоассоциативны. На практике это означает следующее:

- Цепочки из одних `??` дают одинаковый результат в PH8 и в PHP: `$a ?? $b ?? $c` вернёт первое значение, не равное `null`.
- Выражение с `||` слева от `??` разбирается одинаково: `$a || $b ?? $c` везде означает `($a || $b) ?? $c`. Левая часть здесь всегда булева, а не `null`, поэтому `$c` никогда не будет использовано.
- Различие появляется, когда `??` стоит левее `||`. Выражение `$a ?? $b || $c` в PHP означает `$a ?? ($b || $c)`, а в PH8 `($a ?? $b) || $c`. Результаты могут отличаться, например `5 ?? 0 || 0` даёт `int(5)` в PHP и `bool(true)` в PH8.
- С `&&`, тернарным оператором и присваиваниями поведение `??` в PH8 и в PHP совпадает.

Если `??` и `||` встречаются в одном выражении, всегда указывайте порядок скобками:

```php
$x = $a ?? ($b || $c);
$y = ($a ?? $b) || $c;
```


### 7.5. Что считать безопасным

Без скобок можно спокойно писать всё, что одинаково в Си и в PHP: арифметику с `* / %` и `+ -`, сравнения, `==`, `!=`, `===`, `!==`, побитовые `&`, `^`, `|`, логические `&&`, `||`, присваивания и вызовы вида `!$a->b`, `!$a[0]`. Эти выражения в PH8 и PHP разбираются одинаково.

## 8. Языковые конструкции


### 8.1. Компиляция исходного кода: `compile` и `compile_once`

В PH8 имеются две дополнительные языковые конструкции, отсутствующие в Zend PHP: `compile` и `compile_once`. Они предназначены для подключения исходного кода других файлов **на этапе компиляции**, подобно директиве `#include` в языке C.

- `compile "STRING_LITERAL"` — подключает исходный код указанного файла. Повторное использование этой конструкции приводит к повторному подключению файла.
- `compile_once "STRING_LITERAL"` — подключает исходный код указанного файла только один раз. Повторные обращения к тому же файлу через `compile_once` игнорируются. По смыслу конструкция аналогична `#include` с `#pragma once` в C/C++.

Аргумент обеих конструкций должен быть строковым литералом.

Подключаемый код обрабатывается компилятором как часть исходной программы. При этом границы синтаксических конструкций не могут пересекать границу подключаемого файла: например, нельзя начать заголовок цикла `for` в одном файле, а завершить его с помощью подключаемого кода. Эти конструкции предназначены для подключения исходного кода, а не для подстановки произвольных текстовых фрагментов внутрь синтаксических конструкций.

**Пример**

Файл `main.php`:

```php
<?php

echo 'Hello, world!', PHP_EOL;

compile_once "ct2.php";
compile_once "ct2.php";

echo 'Hello, world!!', PHP_EOL;

compile "ct2.php";

?>
```

Файл `ct2.php`:

```php
<?php

echo 'Hello, world from an included file!', PHP_EOL;

?>
```

Результат выполнения:

```text
Hello, world from an included file!
Hello, world!!
Hello, world from an included file!
```

Первый вызов `compile_once` подключает `ct2.php`, а второй не приводит к повторному подключению. Конструкция `compile` подключает этот же файл ещё раз, поэтому сообщение из него выводится повторно.

### 8.2. `echo` в контексте вызова функции:

`echo` - может быть использована в выражении, ведет себя как функция. `is_callable('echo')` == TRUE;


### 8.3. Не поддерживаемые языковые конструкции

`yield` (генераторы) и `match` - не поддерживаются. 

`Namespaces` - не поддерживаются (парсер их разбирает, но не использует)



## 9. Исключения и особенности их обработки

В Zend PHP классы `Error` и `Exception` реализуют интерфейс `Throwable`. Если в ZendPHP требуется создать класс, который можно использовать в `throw`, то
этот класс должен реализовать интерфейс `Throwable`:

```php

class MyClass implements Throwable {
...
}
```

В PH8 `Throwable` - это не интерфейс а полноценный класс, от которого унаследованы `Error` и `Exception`:

```php

class MyClass extends Throwable {  // extends вместо implements
...
}
```

В частности, можно написать `throw new Throwable()` и такой код скомпилируется и будет работать.



Вирутальная машина может генерировать исключения в процессе исполнения файла: например, деление на ноль, или вызов неизвестной функции, или доступ к неизвестному свойству объекта и так далее.

Однако, если исключение случилось при инициализации статических атрибутов класса или констант класса, то весь класс будет помечен компилятором как "плохой": при попытке создать экземпляр класса будет возвращен NULL, при попытке доступа к аттрибутам класса будет выброшено исключение.

Пример:

```php
class MyClass {
  const A = 1 / 0;  // <-- деление на ноль
}
```

Такой класс скомпилируется, скрипт запустится, но создать экземпляр класса не выйдет.

Если исключение случилось при инициализации обычного аттрибута (не константы и не статического аттрибута), то
такое исключение не приведет к останову программы, но и проигнорировано не будет: произойдет отображение ошибки, но выполнение продолжится дальше. Аттрибут, при инициализации которого произошло исключение получит значение `null`;


Если исключение произошло в аргументе функции\метода по умолчанию, т.е.:

```php
function test(int $a = 1/0) {
}


test();

```

то такой код выбросит исключение.

**Полноценно перехватить такие исключения нельзя** - после отработки `catch()` блока выполнение продолжается с места, в котором произошло исключение, со следующей инструкции:

```php

try {
  test();                        // 1. вызов test() без апарметров, будет использоваться значение по умолчанию.
  die ("Oops");                  // 3. Продолжаем отсюда
} catch(Error $e) {
  echo 'Caught!', PHP_EOL;       // 2. Поймали
}

```
